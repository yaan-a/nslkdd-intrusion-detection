# NSL-KDD Intrusion Detection

This project replicates the paper _Machine learning-based intrusion detection
framework using NSL-KDD dataset_, published in **Discover Artificial
Intelligence** by Springer Nature in 2026. The paper is fully open access:

- Paper: <https://link.springer.com/article/10.1007/s44163-026-01930-9>
- Dataset: NSL-KDD
- Kaggle download: <https://www.kaggle.com/datasets/hassan06/nslkdd>
- Original UNB source: <https://www.unb.ca/cic/datasets/nsl.html>

NSL-KDD contains 148,517 records: 125,973 training records and 22,544 test
records. Each record has 41 network-traffic features and a class label. The
project treats the task as binary intrusion detection: `normal` traffic is the
negative class and every attack type is the positive class.

The replication evaluates Logistic Regression, K-Nearest Neighbors, Naive
Bayes, Decision Tree, Random Forest, and a proposed stacking classifier. The
reported metrics include accuracy, precision, recall, F1 score, and ROC-AUC.

> **Note on the paper.** The paper compares Logistic Regression, KNN, Naive
> Bayes, Decision Tree, Random Forest and SVM (several kernels) using a random
> 80:20 split of the merged data. It does not include a stacking classifier.
> The stacking model in this repository is this project's own addition.

## Dataset

NSL-KDD is a public benchmark (source links above). The files used here are
stored in `data/`:

- `KDDTrain+.csv` and `KDDTest+.csv`: the official train and test files
- `NSL-KDD_merged.csv`: both files merged, used for the paper protocol. It has
  an extra `source_file` column (`train` or `test`) recording which official
  file each row came from.

Two evaluation protocols are supported:

| Protocol | Command | Description |
|---|---|---|
| Paper protocol | `replicate_nslkdd.py --merged-csv ...` | Merged data, random 80:20 split, as in the paper |
| Official protocol | `export_model.py` or `replicate_nslkdd.py --train ... --test ...` | Train on `KDDTrain+`, test on `KDDTest+` (contains attack types unseen in training) |

## Algorithms

- Logistic Regression
- K-Nearest Neighbors
- Naive Bayes
- Decision Tree
- Random Forest
- Stacking classifier (Random Forest, Decision Tree, KNN, Bernoulli Naive
  Bayes; Logistic Regression as the final estimator)

## Evaluation Metrics

- Accuracy
- Precision
- Recall
- F1-score
- ROC-AUC
- Confusion matrix
- Per-attack-type and per-family recall (official protocol)

## Project Files

- `replicate_nslkdd.py`: replication script (paper protocol and official protocol)
- `export_model.py`: trains the official-protocol stacking model and exports the inference bundle
- `analyze_attack_types.py`: per-attack-type recall of the official-protocol model on `KDDTest+`
- `app_streamlit.py`: Streamlit app for classifying one connection at a time
- `nslkdd_stacking_colab.ipynb`: Colab notebook version of the stacking experiment
- `utils.py`: small helper (`to_binary_label`) used to demonstrate automated testing
- `tests/test_utils.py`: unit tests for the helper
- `.github/workflows/python-test.yml`: GitHub Actions workflow that runs the unit tests
- `data/`: dataset files
- `model/`: exported model bundles (`nslkdd_model.pkl`, `nslkdd_stacking_proposed.pkl`) and `metrics.json`
- `results/`: results generated by the scripts, including `per_attack_recall.csv` and `per_family_recall.csv`
- `requirements.txt`: Python dependencies

## Setup

Run everything inside a local Python virtual environment.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

The committed model bundle `model\nslkdd_model.pkl` was created with
scikit-learn 1.9.1. Loading it with a different scikit-learn version prints an
`InconsistentVersionWarning`. In a test with scikit-learn 1.8.0 the results were
identical, but use 1.9.1 to reproduce results exactly.

Quick smoke test:

```powershell
python replicate_nslkdd.py --merged-csv data\NSL-KDD_merged.csv --sample 20000
```

Here, `--merged-csv` tells `replicate_nslkdd.py` to use the existing merged
file and run the paper protocol. It does not merge files and it is not needed
again when `data\NSL-KDD_merged.csv` already exists.

Full paper-protocol run, all models including the proposed stacking model:

```powershell
python replicate_nslkdd.py --merged-csv data\NSL-KDD_merged.csv
```

Save the fitted stacking model and preprocessing as a PKL:

```powershell
python replicate_nslkdd.py --merged-csv data\NSL-KDD_merged.csv --save-pkl
```

The default output is `results\nslkdd_stacking_proposed.pkl`. Use `--pkl-out path\to\model.pkl` to choose a different path.

Build the official-protocol bundle for the Streamlit app:

```powershell
python export_model.py
streamlit run app_streamlit.py
```

`export_model.py` expects the official files `data\KDDTrain+.csv` and
`data\KDDTest+.csv` by default. It writes the fitted inference bundle to
`model\nslkdd_model.pkl` and its evaluation metrics to `model\metrics.json`.
The Streamlit app loads that bundle and provides a form for classifying one
network connection at a time. The app's **Model** selector also supports
`model\nslkdd_stacking_proposed.pkl`, the stacking model saved by the paper
protocol. Its metrics are read from `results\metrics_paper.csv`, while the
input defaults and ranges are derived from `data\NSL-KDD_merged.csv`.
The app displays the selected model's evaluation metrics and can randomize test
inputs.

If the files are stored elsewhere, pass their paths explicitly:

```powershell
python export_model.py --train path\to\KDDTrain+.csv --test path\to\KDDTest+.csv
streamlit run app_streamlit.py
```

Keep the terminal running while using the app, then open the local URL shown by
Streamlit (normally `http://localhost:8501`). Dependencies for both scripts
are in `requirements.txt`.

### What `export_model.py` exports

The script does **not** train several models and select the one with the best
test score. It always trains the project's official stacking model using:

- Random Forest (`n_estimators=100`)
- Decision Tree
- K-Nearest Neighbors (`n_neighbors=5`)
- Bernoulli Naive Bayes
- Logistic Regression as the final estimator

The base models are combined by `StackingClassifier` with five-fold
cross-validation and probability-based stacking. The script fits the scaler on
the official training data and fits categorical encoders using categories from
both official files, evaluates the resulting fixed stacking model on the
official test data, and exports the model together with encoders, scaler,
feature lists, input defaults/ranges, and evaluation metrics. Therefore,
`model\nslkdd_model.pkl` is the **proposed stacking model**, not an automatically
chosen “best model.”

The two original files can also be used directly with the same paper protocol:

```powershell
python replicate_nslkdd.py --train data\KDDTrain+.csv --test data\KDDTest+.csv
```

### Per-attack-type analysis

```powershell
python analyze_attack_types.py
```

Loads `model\nslkdd_model.pkl` (it does not retrain), applies the same
preprocessing as `export_model.py` to `KDDTest+`, and writes
`results\per_attack_recall.csv` and `results\per_family_recall.csv`. The script
checks its confusion matrix against the one stored in the bundle and stops
without writing anything if they differ. If `data\KDDTrain+.csv` or
`data\KDDTest+.csv` are missing, it recovers the official split from the
`source_file` column of the merged file.

### Run the unit tests

```powershell
python -m unittest discover -s tests -v
```

Deactivate the environment when finished:

```powershell
deactivate
```

## Results

### Official protocol (train on `KDDTrain+`, test on `KDDTest+`)

Stacking model, from `model/metrics.json` (22,544 test records: 9,711 normal and
12,833 attacks):

| Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|
| 78.35% | 96.72% | 64.15% | 77.14% | 0.9742 |

Confusion matrix: TN = 9,432, FP = 279, FN = 4,601, TP = 8,232.

The model rarely raises false alarms (high precision) but misses about 36% of
attacks (low recall) on this test set, which includes attack types absent from
the training data.

### Per-attack-type recall: official protocol (KDDTest+)

Stacking model, threshold 0.5, 12,833 attack records across 37 attack types, of
which 17 do not appear in `KDDTrain+`. Overall recall is 64.15%. Full results:
`results/per_attack_recall.csv` and `results/per_family_recall.csv`.

By attack family and by whether the attack type appears in `KDDTrain+`:

| Group | Attack types | Records | Recall | Missed |
|---|---|---|---|---|
| DoS | 11 | 7,460 | 81.9% | 1,352 |
| Probe | 6 | 2,421 | 81.9% | 438 |
| R2L | 13 | 2,885 | 4.6% | 2,753 |
| U2R | 7 | 67 | 13.4% | 58 |
| Types seen in training | 20 | 9,083 | 76.2% | 2,163 |
| Types not in training | 17 | 3,750 | 35.0% | 2,438 |

Family and seen/unseen combined:

| Family | Seen in training: records, recall | Not in training: records, recall |
|---|---|---|
| DoS | 5,741, 99.8% | 1,719, 22.1% |
| Probe | 1,106, 100.0% | 1,315, 66.7% |
| R2L | 2,199, 3.7% | 686, 7.3% |
| U2R | 37, 10.8% | 30, 16.7% |

The ten attack types with the most missed records:

| Attack type | Family | In `KDDTrain+` | Records | Detected | Recall |
|---|---|---|---|---|---|
| guess_passwd | R2L | yes | 1,231 | 1 | 0.1% |
| warezmaster | R2L | yes | 944 | 77 | 8.2% |
| processtable | DoS | no | 685 | 105 | 15.3% |
| apache2 | DoS | no | 737 | 273 | 37.0% |
| mscan | Probe | no | 996 | 562 | 56.4% |
| snmpguess | R2L | no | 331 | 0 | 0.0% |
| mailbomb | DoS | no | 293 | 0 | 0.0% |
| snmpgetattack | R2L | no | 178 | 0 | 0.0% |
| httptunnel | R2L | no | 133 | 46 | 34.6% |
| buffer_overflow | U2R | yes | 20 | 3 | 15.0% |

Observations (descriptive; causes have not been investigated):

- DoS and Probe attacks are detected almost perfectly when the attack type is
  in the training data, and much less well when it is not.
- R2L and U2R attacks are detected poorly whether or not the type appears in
  training.
- Seen-in-training does not mean well-represented: `guess_passwd` has 53 records
  in `KDDTrain+` and 1,231 in `KDDTest+`, and `warezmaster` has 20 and 944.
- Some unseen types are detected well (`saint`: 315 of 319), others not at all
  (`mailbomb`: 0 of 293).

Limits: U2R has only 67 test records and several attack types have fewer than
20, so those rates are noisy. The family assignment uses the mapping in
`analyze_attack_types.py`; a few attack names (for example `worm`) are
classified differently in some papers. These numbers describe the stacking
model only, not the paper's Random Forest or SVM models.

### Paper protocol (merged data, random 80:20 split)

Produced by `replicate_nslkdd.py --merged-csv data\NSL-KDD_merged.csv` on the
merged file (148,517 rows). Random 80:20 split: 118,813 training and 29,704
test records (48.1% attacks in both). VIF filtering dropped 8 features, leaving
32.

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC | 5-fold CV acc. | Paper accuracy |
|---|---|---|---|---|---|---|---|
| Logistic Regression | 92.69 | 93.50 | 91.14 | 92.31 | 0.9756 | 92.54 ± 0.47 | 96.72 |
| K-NN | 98.72 | 98.86 | 98.49 | 98.67 | 0.9965 | 97.64 ± 0.06 | >99 |
| Naive Bayes | 91.89 | 95.40 | 87.36 | 91.21 | 0.9786 | 91.87 ± 0.31 | 89.71 |
| Decision Tree | 99.43 | 99.37 | 99.45 | 99.41 | 0.9945 | 98.98 ± 0.19 | ~97 |
| Random Forest | 99.59 | 99.73 | 99.41 | 99.57 | 0.9999 | 99.30 ± 0.08 | 99.87 |
| Stacking (proposed) | 99.59 | 99.70 | 99.44 | 99.57 | 0.9999 | 99.33 ± 0.11 | not in paper |

The stacking model matches, but does not exceed, Random Forest on this split.
"Paper accuracy" is the value reported in the paper (some are given only
approximately). The paper's SVM results are not replicated here.

### Comparison

Under the paper's protocol all six models reach 91.9% to 99.6% accuracy. Under
the official protocol the stacking model reaches 78.35% accuracy and 64.15%
recall. The two runs differ in more than the split:

- the paper-protocol run keeps 32 features after VIF filtering, while the
  official-protocol export keeps 34;
- the other models have not yet been evaluated under the official protocol.

The gap therefore cannot be attributed to the split alone. The per-attack-type
results above show that the official-protocol misses are concentrated in R2L and
U2R attacks and in attack types absent from training, but they describe one
model on one test set. Evaluating all models under one protocol with identical
features is tracked in issue #3.

## Automated checks

`.github/workflows/python-test.yml` runs `python -m unittest discover -s tests -v`
on pushes to `main` and on pull requests into `main`. The tests cover only the
label helper in `utils.py` (`normal`, in any capitalization, maps to 0 and any
attack name maps to 1). A passing check does not validate the datasets, the
training pipeline or model performance.

## Limitations

NSL-KDD is an older benchmark and does not represent modern encrypted, cloud or
IoT traffic. Results here are benchmark-level performance, not real-world
deployment performance.
